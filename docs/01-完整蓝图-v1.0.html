01 · OVERVIEW

背景与定位

为什么在「ai-job-search」之外还需要一个中国版？核心差异在于三件事：平台生态、简历形态、岗位语义。

原项目启发（值得继承）

  • 命令式工作流：/setup → /scrape → /rank → /apply，把复杂求职拆成可复现步骤
  • 双 Agent 起草-评审：求职信/简历由起草 Agent 生成、独立评审 Agent 批判修订
  • 门户适配器解耦：每个招聘平台一个独立 skill/适配器，可插拔扩展
  • PDF 验证循环：编译后视觉检查 + ATS 文本层校验
  • 诚实规则：资料不支持的技能标记为差距，绝不虚构

必须本土化改造（中国市场差异）

  • 平台无开放 API：Boss直聘等仅对企业端开放接口 → 采用浏览器自动化 + 登录态复用
  • 风控严苛：反爬策略强、账号封禁成本高 → 半自动模式、频率纪律、人工闸门
  • 简历中文 + ATS：北森/Moka/用友大易解析中文简历，关键词覆盖率是核心
  • 岗位语义特殊：PM 岗位按 行业×方向×级别 三维分化（B端/C端/AI产品/数据产品…）
  • LLM 选型：需兼容 DeepSeek / 通义 / GLM 等国内模型，而非仅 Claude
产品定位一句话：一个运行在你本地电脑上的「产品经理求职副驾驶」——它替你自动找（跨平台搜岗、按 JD 匹配评分）、帮你写（定制简历、打招呼语、面试模拟）、帮你管（投递看板、跟进提醒），但不替你发（所有对外动作需人工确认）。

设计原则

① 半自动而非全自动
「找与评」自动，「发与投」人工。投递、打招呼、回复消息均需人工确认，规避封号风险。
② 隐私本地化
档案、简历、聊天记录全部本地 SQLite 存储，凭证留在浏览器，符合个人信息保护要求。
③ PM 语义优先
匹配引擎理解「行业×方向×级别」，而非简单关键词命中；技能雷达按产品经理能力模型建模。

05 · PLATFORM LAYER

平台接入层设计（重点：Boss直聘）

中国大陆招聘平台均无公开的职位开放 API（Boss直聘仅对企业端开放，需企业认证）。因此接入层统一采用「浏览器自动化 + 复用用户本机登录态」方案，并建立统一适配器接口与风控纪律。

接入方案对比

方案可行性稳定性合规风险结论
官方 API / 企业开放平台 ❌ 个人开发者无法申请 —— 不可行
直连 wapi 接口（如 joblist.json） 社区逆向可用低（接口随时变更）高（绕过登录态，易触发风控） 不采用
Playwright 持久化浏览器上下文 ✅ 扫码登录一次，会话持久化高（跟随页面改版即可）中（需频率纪律） 主方案
CDP 复用 Chrome 登录态（OpenCLI 模式） ✅ 凭证不出浏览器高中 备选
集成开源 boss-cli（kabi-boss-cli） ✅ 已含搜索/投递/打招呼/面试接口中（随上游更新）中（其内置 1.5s 风控延迟，可复用其经验） 参考集成
接入原则：① 只用自己的账号登录态，凭证留在浏览器；② 只自动化「读与评」（搜索/详情/公司/状态），「写与投」（打招呼/投递/回复）一律走人工确认闸门；③ 遇到验证码或异常风控提示，立即停止并通知用户人工处理，绝不尝试绕过。

Boss直聘适配器（boss-adapter）能力规格

能力方法输入 → 输出人工闸门
职位搜索search_jobsquery + 城市码 + 筛选（薪资/经验/学历/行业/融资阶段） → 职位卡片列表（标题/公司/薪资标签/链接）无需
职位详情get_job_detailjobId → JD 全文 + 岗位标签 + 公司信息 + 沟通 BOSS 身份无需
公司画像get_company_profilecompanyId → 规模/阶段/行业/在招职位无需

打招呼 / 投递send_greetingbossId + 个性化话术 → 发送结果必须人工确认

风控纪律（内置默认值，可配置）

请求节奏
  • 搜索间隔：3–8 秒随机抖动（默认 5s）
  • 打招呼间隔：≥ 1.5s + 随机 1–3s（参考 boss-cli 经验值）
  • 单次任务上限：搜索 ≤ 20 页；打招呼 ≤ 50 次/天
  • 整点高峰（9:00–11:00）可配「保守模式」降频
异常处置
  • 检测到验证码 / 「操作频繁」提示 → 立即中止，写入事件日志并桌面通知
  • 同 IP 登录异地提醒 → 暂停所有写操作
  • 操作失败重试 ≤ 2 次，指数退避
  • 每日写操作总次数超限 → 锁死至次日

统一适配器接口（平台无关契约）

# adapters/base.py — 所有平台实现该协议
class JobAdapter:
    platform: str                 # "boss" | "lagou" | "liepin" ...

    def search_jobs(self, query: str, city: str,
                      filters: dict) -> list[JobCard]: ...
    def get_job_detail(self, job_id: str) -> JobDetail: ...
    def get_company_profile(self, company_id: str) -> Company: ...
    def list_conversations(self) -> list[Conversation]: ...

    # —— 以下为写操作，调用前必须经过 confirm_gate ——
    def send_greeting(self, boss_id: str, message: str) -> bool: ...
    def reply_message(self, thread_id: str, text: str) -> bool: ...

# 输出统一为 envelope：{"ok": true, "data": ..., "risk": "low"}

所有适配器输出结构化 JSON（envelope 格式），供智能层消费。平台差异（选择器、登录方式、字段名）被完全封装在适配器内部。

参考生态：kabi-boss-cli（BOSS直聘 CLI，含 Cookie 提取/搜索/投递/面试查询，内置 1.5s 风控延迟）、OpenCLI（复用 Chrome 登录态的通用 CLI 枢纽，已支持 Boss直聘）。本项目适配器设计与其保持同思路，但把「写操作」默认改为人工确认，进一步降低风险。

06 · PM INTELLIGENCE

PM 专属智能引擎

这是与通用求职工具差异化的核心：让引擎理解产品经理岗位的语义，而不只是做关键词匹配。

6.1 五维匹配评分模型

图 3 · 五维评分 + 一票否决项（评分 85+ 进入「推荐投递」，60–85 进入「备选」，<60 或触发否决进入「不投」）

评分的同时生成差距分析报告：指出该 JD 的「加分关键词」与「硬伤」，供简历定制与自我提升使用。评分权重可通过 /rank --weights 按用户当前求职阶段调整（如冲刺期加大行业权重）。

/radar 将档案证据与目标方向（如「AI 产品经理」）对照，输出差距热力图 + 优先级建议 + 学习资源清单（对标 /upskill）。

6.3 简历诊断器（面向国内 ATS）

  • 关键词覆盖率：JD 解析出的硬技能/软技能/行业词，逐一检测简历文本覆盖与自然融入度
  • STAR 量化检测：识别「做过」而非「做成过」的条目，自动给出 STAR 改写建议（结果必须可量化）
  • ATS 模拟解析：以北森 / Moka / 用友大易 的解析规则模拟提取，检查联系方式是否为字面文本、排版是否错乱（警告：嵌套表格/文本框/矢量文字提取失败率高）
  • 中文排版规范：一页/两页控制、避免孤立标题、字体嵌入（转 PDF 时必须嵌入中文字体）
  • 诚实规则：缺失能力如实标为差距，绝不虚构项目（继承原项目原则）

6.4 面试模拟器（中国 PM 题型）

题型说明产出
行为面（STAR）「讲一个你推动跨部门协作的项目」基于档案真实经历映射 3-5 条 STAR 回答骨架
产品设计题「为 60 岁老人设计一个健康管理 App」拆解框架：用户→场景→功能→优先级→MVP
估算/费米题「北京一年卖出多少杯咖啡」拆解链路 + 合理假设 + 验算（附方法论）
数据/指标题「DAU 下降 10% 如何排查」指标体系 + 排查路径 + 归因方法
公司/竞品研究目标公司产品矩阵与竞对格局一页简报（公司信源：官网/公众号/即刻/脉脉/财报）

支持「模拟面试对话模式」：AI 扮演面试官连续追问，用户口述/打字作答后逐题点评。研究类信息遵循「verify-before-use」，AI 生成的关于公司的事实需附来源并提示人工核实。

6.5 作品集管理

产品经理求职的差异化筹码。维护 profile/portfolio/ 目录：PRD 案例、原型链接、数据复盘、竞品分析；/portfolio 生成一页「作品集索引」附在简历后，或生成可分享的离线 HTML 作品集主页。

模块规格（命令一览）

继承原项目「斜杠命令」风格，共 10 个命令 + 1 个安全命令。每个命令是 Agent 工作流的一次编排入口。

/apply 核心流程（起草-评审双 Agent + 人工闸门）

  1. 解析：从职位详情提取结构化 JD（行业/方向/级别/薪资/硬技能/软技能/红线）
  2. 评估：五维评分 + 否决检查，输出匹配度与差距
  3. 起草：Agent A 依据档案与差距报告生成定制简历（调序/换词/补量化，不虚构）与个性化打招呼语（依据 JD 亮点 + 用户项目，拒绝模板话术）
  4. 评审：Agent B 独立研究该公司（官网/新闻/产品），批判草稿的匹配度与真实性，产出修订意见
  5. 修订 + 校验：生成 PDF（HTML→Chromium 打印，嵌入中文字体），ATS 模拟解析校验，视觉检查一页/两页与版式
  6. 呈现 + 人工确认：输出简历 PDF + 打招呼语 + 校验清单，等待用户确认后才调用适配器写操作

09 · TECH STACK

技术选型

层选型理由
语言/运行时Python 3.11+（uv 管理）Playwright、boss-cli 生态同源，便于直接复用开源适配器逻辑；uv 保证隔离安装
LLM 接入DeepSeek / 通义千问 / GLM（OpenAI 兼容），可选 Claude国内可用、成本低；通过统一 LLM 适配层切换，prompt 与流程无关
浏览器自动化Playwright（持久化 user-data-dir 上下文）扫码登录一次、会话复用；可控频率与验证码感知；跨平台
简历生成HTML → PDF（Chromium print）+ 中文字体嵌入；xelatex 备选中文排版可控（原项目 LaTeX 对中文字体配置较重），ATS 文本层天然友好
存储SQLite + JSONL 快照单文件、零运维、隐私本地化
看板/报告自包含 HTML（内联 SVG/JS，无外部依赖）继承原项目 /html-report 理念，离线可查可打印
调度cron / 系统计划任务触发 /scrape + /track每日晨间巡检自动化
关于简历工具链的选择：原项目使用 LaTeX（xelatex），其对中文需要 fontspec + 中文字体配置，跨平台折腾成本高。本设计默认「HTML → Chromium 打印 PDF」，既保证中文排版质量，又让 ATS 文本层可控；同时保留 /add-template 式的模板注册机制（支持任意可编译为 PDF 的工具链）。
10 · COMPLIANCE & RISK

合规与风控设计

合规定位
  • 个人效率工具，非商业爬虫/数据转售
  • 仅使用本人账号登录态；凭证永不离开浏览器（CDP 方案下连本地文件都不落盘）
  • 遵守《个人信息保护法》：简历、沟通等个人信息仅本地存储，不上传任何第三方服务（LLM 调用前可配置脱敏）
  • 不绕过验证码、不批量注册、不刷量
平台风控（Boss直聘）
  • 读操作限频：搜索 3–8s 随机间隔，单任务 ≤ 20 页
  • 写操作闸门：打招呼/投递/回复一律人工确认；单日 ≤ 50 次
  • 验证码 / 异常提示 → 立即停机并通知，绝不硬闯
  • 配置「保守时段」（9:00–11:00 高峰降频）与全局熔断开关
风险声明：① 平台规则可能随时变更，自动化能力可能失效，本项目不承诺绕过任何风控；② 过度使用自动化（尤其写操作）存在账号被限流/封禁风险，用户需自行承担；③ 所有 AI 生成的关于公司的事实信息需人工核实（verify-before-use）。
11 · ROADMAP

路线图

阶段周期里程碑验收标准
MVP第 1–2 周 /setup 建档 · /scrape（Boss直聘）· /rank 评分 · /track 看板 能对 50 个真实 Boss直聘职位完成抓取与评分，看板正确统计
V1第 3–6 周 /apply 简历生成 · 打招呼起草+人工闸门 · 投递追踪 · 消息提醒 完成 1 次真实投递闭环（人工确认后），简历 ATS 校验通过
V2第 7–10 周 /interview 面试模拟 · /radar 技能雷达 · 拉勾/猎聘适配器 · 报告导出 覆盖 ≥3 平台；面试题库覆盖 4 类题型；支持离线报告分享

里程碑设计遵循「先读后写、先单平台后多平台」：MVP 阶段只做读操作（搜索/评分），确认风控稳定后，V1 才引入带人工闸门的写操作。

12 · REPO LAYOUT

项目目录结构

pm-scout/
├── cli.py                          # 命令入口（typer/argparse）
├── profile/                        # 个人资料区（.gitignore，绝不入库）
│   ├── profile.json                # 求职档案 + 求职意向
│   ├── resume_base/                # 简历母版（各方向 2-3 份）
│   └── portfolio/                  # 作品集（PRD/原型/复盘）
├── adapters/                       # 平台适配器（统一 JobAdapter 协议）
│   ├── base.py
│   ├── risk.py                     # 频率/限额/熔断
│   ├── boss/                       # Boss直聘 · P0（Playwright）
│   ├── lagou/  liepin/  zhaopin/   # P1/P2（脚手架生成）
│   └── template/                   # /add-platform 脚手架模板
├── engine/                         # PM 智能引擎
│   ├── jd_parser.py                # JD → 结构化（行业/方向/级别/技能/红线）
│   ├── matcher.py                  # 五维评分 + 否决 + 差距
│   ├── resume_gen.py               # HTML→PDF 简历生成（双 Agent）
│   ├── resume_diag.py              # 覆盖率 / STAR / ATS 模拟
│   ├── skill_radar.py              # 八维能力模型
│   ├── interview_gen.py            # 面试包生成
│   └── llm.py                      # LLM 适配层（DeepSeek/通义/GLM/Claude）
├── commands/                       # 命令编排（每个命令一个模块）
├── storage/                        # SQLite + JSONL 快照
├── reports/                        # 自包含 HTML 看板/报告产物
├── salary_lookup.py                # 本地薪资对标（借鉴原项目）
├── templates/                      # 简历/打招呼语/跟进模板
└── SETUP.md

「双配置根」原则继承自原项目：adapters/（可移植的平台技能）与 commands/ + engine/（编排与智能）分离，新增平台只改 adapters/，新增智能不碰平台。

灵感来源：github.com/MadsLorentzen/ai-job-search（MIT License）—— Claude Code 驱动的求职智能体框架，本设计在其「命令式工作流 / 门户适配器解耦 / 起草-评审双 Agent / PDF 验证循环」基础上，针对中国大陆市场与产品经理岗位语义完成本土化再设计。
