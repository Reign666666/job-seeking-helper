02 · SCOPE

定位与范围

本期做什么（IN）

  • 简历上传与本地解析（PDF / Word / 纯文本）
  • JD 粘贴与结构化解析（行业 / 方向 / 级别 / 技能 / 红线）
  • 岗位匹配度分析：总分 + 五维分解 + 否决项 + 差距清单
  • 简历优化建议：关键词覆盖率、STAR 量化改写示例、减分项
  • 打招呼话术：3 版个性化话术（可复制）
  • 面试准备建议：针对该 JD 的题型 + 答题思路 + 素材清单
  • 隐私保护：全本地处理 + 发送 LLM 前脱敏 + 不留痕选项

本期不做（OUT）

  • ❌ 平台自动化（自动搜索 / 自动投递 / 自动打招呼）—— 二期
  • ❌ 多平台数据抓取 —— 二期
  • ❌ 投递追踪看板 / 账号体系 —— 二期
  • ❌ 面试模拟对话训练 —— 二期（本期只给建议与题库）
  • ❌ 云端部署 —— 与「仅保留在本地」冲突，默认不做

一句话：本期 = 「简历 × JD 智能分析咨询师」，浏览器打开即用，分析完数据不留服务器。

03 · USER FLOW

用户操作流程（4 步）

STEP 1上传简历拖拽或点击上传 PDF / Word / TXT，本地解析并预览提取结果
→
STEP 2填写目标 JD粘贴目标岗位 JD 文本（从 Boss直聘复制即可）
→
STEP 3开始分析点击分析，进度提示「解析中 → 脱敏中 → 分析中」
→
STEP 4查看四项结果匹配度 / 优化建议 / 打招呼话术 / 面试准备，可复制、可导出
图 1 · 第一期数据流：全程本机，仅「脱敏后的简历文本 + JD」发送至用户自选的大模型 API
关键体验设计：整个流程控制在 3 分钟内出结果；结果区四块内容可单独复制；支持「仅本次分析，不保存任何记录」的模式，满足敏感场景。

版本风格特征

05 · PRIVACY

隐私与安全设计（本期重点）

核心承诺：除「你主动选择的大模型服务商」外，不向任何服务器发送数据；简历原文与 JD 仅保存在本机；默认开启脱敏。

数据流与本地化

  • 简历解析、JD 解析、脱敏均在本机完成（浏览器或本地服务）
  • 历史记录（可选）仅存 localStorage 或本地 SQLite 文件，不设账号、无云同步
  • 提供「用完即焚」模式：关闭页面即清除全部数据
  • 提供「一键清除历史」按钮

LLM 调用前脱敏（默认开启）

  • 规则脱敏：手机号 / 固话 / 邮箱 / 微信号 / 身份证 / 住址 → 替换为占位符（如 [手机号]）
  • 姓名可选脱敏：替换为「候选人」
  • 展示「即将发送给模型的内容」预览，用户可查看后再确认
  • 页面明示：调用哪家模型、发送了什么内容

隐私模式矩阵

开关默认效果
脱敏发送开敏感字段替换为占位符后再发 LLM
姓名脱敏可配简历中的姓名替换为「候选人」
保存历史可配本地保存分析记录（可一键清除）
用完即焚可配本次分析结果关闭页面即销毁

需向用户如实说明的唯一例外：脱敏后的简历文本与 JD 会发送至用户自行配置的大模型服务商（如 DeepSeek），这是「AI 分析」功能的前提，页面须以文字明示。

06 · TECH OPTIONS

技术方案（已确认）

✅ 2026-08-15 已确认的技术决策：① 采用方案 A · 本地网页服务（FastAPI 本地起服务 + 浏览器访问 localhost）；② 大模型由用户自带 API Key（OpenAI 兼容接口，DeepSeek/通义/GLM 任选，页面内配置）；③ 分析历史本地保存、提供一键清除；④ 简历解析支持 PDF + Word + 纯文本 全格式。
方案 A · 推荐

本地网页服务（Local Web App）

  • 形态：一条命令启动本机服务，浏览器打开 localhost:8765
  • 解析：后端解析 PDF/Word（pdfminer / mammoth），支持最全
  • LLM：后端调用，无浏览器跨域(CORS)限制，各家大模型 API 通吃
  • 存储：本地 SQLite / 文件，历史可管可清
  • 扩展：二期 Boss直聘自动化可直接挂载同一后端（Playwright）
  • 成本：需本机有 Python 3.11+ 环境
方案 B

纯静态单网页（Static Page）

  • 形态：单个 HTML 文件，双击浏览器打开即用，零安装
  • 解析：浏览器端解析（pdf.js / mammoth.js），PDF 大文件略慢
  • LLM：浏览器直连模型 API —— 部分国内大模型接口存在 CORS 跨域限制，需逐家实测
  • 存储：仅 localStorage，无文件级导出
  • 扩展：二期自动化需另起后端，与本期形态不衔接
  • 成本：零依赖，最轻量
我的建议：方案 A。理由：① 彻底规避 CORS 问题，模型选型自由（DeepSeek/通义/GLM 任选）；② 与「仅保留在本地」承诺最贴合，历史与导出可控；③ 为二期自动化预留同一后端，避免推倒重来。方案 B 的「零安装」优势可用「一键启动脚本」弥补（双击 start.bat 自动拉起服务并打开浏览器）。
07 · API & PROMPT

接口与 Prompt 设计概要

# 后端接口（方案 A，FastAPI）
POST /api/parse_resume      # 上传文件 → 提取文本 + 敏感字段定位
POST /api/parse_jd          # JD 文本 → 结构化(行业/方向/级别/技能/红线)
POST /api/sanitize          # 简历文本 → 脱敏文本（规则引擎）
POST /api/analyze           # 脱敏简历 + JD → 四项结果(JSON)
GET  /api/history           # 本地历史（可关闭）
DELETE /api/history          # 一键清除

# LLM Prompt 三段式（system + resume + jd），输出 JSON schema：
{
  "match": {"score": 87, "tier": "recommend",
            "dimensions": [{"name": "硬技能", "score": 92, "evidence": "…", "gap": "…"}],
            "veto": {"passed": true, "notes": "…"},
            "gaps": ["…"]},
  "resume_tips": {"keywords": {"hit": [], "miss": [], "suggest": []},
                   "rewrites": [{"before": "…", "after": "…"}]},
  "greetings": {"concise": "…", "professional": "…", "enthusiastic": "…"},
  "interview": {"questions": [{"type": "估算题", "question": "…", "approach": "…"}],
                 "probe_points": ["…"], "materials": ["…"]}
}

Prompt 内置规则：以资深产品经理招聘视角评审；只基于简历已有内容，不虚构；输出严格 JSON；公司类事实信息标注「需人工核实」。

08 · ACCEPTANCE

验收标准

  • 流程：上传简历 → 粘贴 JD → 分析 → 四项结果齐全，全程 ≤ 3 分钟（常规模型）
  • 匹配度：五维雷达 + 否决项 + 差距清单正确生成，且能指出简历中具体证据句
  • 优化建议：关键词覆盖率逐词列出；至少 3 条 STAR before→after 改写示例
  • 话术：3 版可复制，符合 Boss直聘打招呼语境与字数限制
  • 隐私：默认脱敏生效（测试简历中的手机/邮箱被替换）；「即将发送给模型的内容」可预览；无任何第三方请求（除用户配置的 LLM）
  • 健壮性：解析失败的简历有降级路径（手动粘贴文本）；LLM 接口报错有友好提示与重试
